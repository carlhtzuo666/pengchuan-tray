## 一、键盘注入（`TextInjector.cs`）

进程内静态工具类，基于 Windows 官方 `SendInput` 直接发键事件。**不引第三方库**（详见文件头注释的取舍说明）。

调用前提（重要）：注入目标是**当前键盘焦点所在输入框**，不是鼠标坐标；调用方必须先让目标输入框获得焦点，否则文字会打进别的窗口。

| 成员 | 说明 | 入参 / 返回 | 主要调用方 |
|---|---|---|---|
| `IsSupported` | 当前平台是否具备注入能力（目前仅 Windows 为 `true`） | 属性 `bool` | `TrayContext.PollClipAsync` |
| `DescribeForegroundWindow()` | 取当前前台窗口的「类名 \| 标题」，**仅用于排障日志**，不记录任何输入内容 | 返回 `string`，如 `Chrome_WidgetWin_1 \| 贴吧` | `TrayContext.PollClipAsync` |
| `PressEnter()` | 发送一次回车（KeyDown + KeyUp），等价用户按 Enter。**语义＝「发送/执行」**：手机「Enter」按钮、`enter=true` 的文字都走它 | 返回 `bool`（事件是否全部入队） | `TrayContext.PollClipAsync`（Enter 按钮事件、`enter=true` 的文字） |
| `PressShiftEnter()` | 发送一次 Shift+Enter（`VK_LSHIFT 0xA0 + 扫描码 0x2A` 包住回车）。**语义＝「换行不发送」**：文本内部的 `\n` 一律走它——聊天类输入框把普通 Enter 当「发送」，用它插换行才不会把草稿发出去；记事本/多行框里等同换行，单行框里无副作用 | 返回 `bool` | `TextInjector.TypeText`（文本内换行） |
| `PressCtrlV()` | 发送 Ctrl+V 组合键（`VK_LCONTROL + 扫描码 0x1D`、`V + 0x2F`）。**保留备用**：实测缺少扫描码的 `VK_CONTROL` 会被部分应用静默忽略 | 返回 `bool` | `FileInjector.PasteFiles`（文件投递粘贴） |
| `TypeText(text, delayMs = 4)` | 逐字符以 Unicode 方式键入任意文本（含中文，绕过输入法）；每字符之间留极小间隔，避免浏览器/Electron 丢字符。**换行特殊处理**：遇到 `\n`/`\r` 不发 Unicode 字符（会被 Windows 编辑控件丢弃），改发 `PressShiftEnter()`；CRLF/LFCR 组合只算一次换行 | `text` 要键入的字符串；`delayMs` 字符间隔毫秒；返回 `bool` | `TrayContext.PollClipAsync`（文字投递主路径） |

内部私有成员：`KEYBDINPUT` / `INPUTUNION`（`Size = 32`，保证 x64 下 `INPUT` 为 40 字节，否则 `SendInput` 直接失败）、`KeyboardKey`（VK + 扫描码按键）、`KeyboardUnicode`（`KEYEVENTF_UNICODE` 字符事件）、`Send`（批量投递）。

已知限制：
- **UIPI**：目标窗口以管理员权限运行、而托盘不是时，注入会被系统拦截（`SendInput` 返回 0，代码会降级为"已复制到剪贴板"提示）。
- 前台焦点必须在目标输入框；托盘不会主动抢焦点。

## 二、文字投递方式（`AppSettings.cs` + `TrayContext.cs`）

> **2026-11-11 变更**：投递方式改由**手机端下拉框**逐条下发，电脑端不再提供菜单选择
> （原「文字接收方式」托盘下拉及其 `SetClipMode` / `RefreshClipModeChecks` 已删除）。

| 成员 | 说明 | 入参 / 返回 | 主要调用方 |
|---|---|---|---|
| `AppSettings.ClipModeInject` / `ClipModeClipboard` | 两种投递方式的常量值（`"inject"` / `"clipboard"`），与手机端 `LanPorts` 中的同名常量取值一致 | 常量 | `TrayContext` |
| `AppSettings.ClipDeliveryMode` | **兜底默认值**，默认 `inject`。只在手机端未下发 `mode`（旧版手机）时生效；老配置文件无此键时保留默认，**不需要 bump SettingsVersion** | `string` | `PollClipAsync` |
| `AppSettings.IsClipInjectMode` | 兜底默认值是否为注入模式（除 `"clipboard"` 外都按注入处理，容错旧值） | 属性 `bool` | `PollClipAsync` |
| `PhoneClient.RemoteClip.Mode` | 本条文字的投递方式，来自手机端 `mode` 字段；空串表示旧版手机未下发 | `string` | `TrayContext.PollClipAsync` |
| `PhoneClient.RemoteClip.Realtime` | 是否实时同步帧（边打边传的打字中间态），来自手机端 `realtime` 字段；**正文可为空，空帧=清空输入框** | `bool` | `TrayContext.PollClipAsync` |
| `TrayContext` 实时帧丢弃分支 | 实时开关关闭（或本机设为仅剪贴板）时，`Realtime=true` 的帧直接 ack 丢弃——打字中间态若落入常规发送分支会被整段键入，越打越重复 | — | `PollClipAsync` |

投递语义（`PollClipAsync`）：
- 收到**有文字**的条目：先写系统剪贴板（兜底）→ 若本条 `mode` 为注入（或缺失且本地默认注入）且平台支持，则 `TypeText` 键入焦点输入框；`enter=true` 时再补一个回车。
- 收到**纯回车事件**（`text` 为空、`enter=true`，由手机「Enter」按钮触发）：只按一次回车，不动剪贴板与输入框内容。
- **文本内部换行**（手机键盘的换行键）：走 `TypeText` → `PressShiftEnter()`，只插行、不发送。两个易混语义就此分开——**文本内 `\n` = Shift+Enter（换行），手机 Enter 按钮 = 普通 Enter（发送）**。
- `mode=clipboard`：只写剪贴板，不碰焦点输入框。

## 三、协议字段（与手机端约定）

| 字段 | 位置 | 说明 |
|---|---|---|
| `X-Clip-Enter: 1` | `POST /api/clip` 请求头 | 表示"这条要回车"；正文仍是纯文本（不改既有契约） |
| `X-Clip-Mode: inject\|clipboard` | `POST /api/clip` 请求头 | 本条的投递方式；缺失时电脑端按本地兜底默认（注入）处理 |
| `enter` | `GET /api/clip/latest` 响应 JSON | `true` = 电脑端送达后按一次回车 |
| `mode` | `GET /api/clip/latest` 响应 JSON | 本条投递方式；旧版手机不下发该字段 |
| `text` 为空 + `enter: true` | 同上 | 纯回车事件（手机「Enter」按钮） |

手机端实现见 `D:\tools\harness-personal\harmony-share\entry\src\main\ets`：
`domain/port/LanPorts.ets`（`ClipItem.enter` / `ClipItem.mode` 与两个 mode 常量）、
`infrastructure/clip/ClipStore.ets`（入队与重发保留 mode）、
`infrastructure/http/HttpServer.ets`（读 `X-Clip-Mode`、下发 `mode`）、
`view/PendingUploadPanel.ets`（下拉框选择与展示）、
`common/ClipModePrefs.ets`（记住用户选择，存于 `share_settings` 的 `clip_delivery_mode` 键）。
